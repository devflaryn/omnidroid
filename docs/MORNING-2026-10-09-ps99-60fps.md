## What made the difference (in-session interleaved A/Bs, ABBA, same live world)

1. **Futex wakes were a thundering herd** (`futex.rs`): one condition variable per guest process and
   `notify_all` on every wake -- each of Roblox's ~7k futex wakes a second woke every waiting thread
   of the process. Per-task park/unpark: **31.0 -> 44.5 fps (6/6 pairs), game CPU halved.**
2. **The display window's thread spun at 0.93 of a core** (`omni-platform` window pump): it removed
   only its own window's messages but waited on any message of the thread. ~16 ms of CPU every frame.
3. **Poll waits**: `poll_keyed` (keyed waits; system host 54 -> 47 ms/frame) and **`poll_slice_ms`
   1000** (a posted signal now wakes poll waiters directly; the 50 ms slice woke ~700 threads 20x/s:
   system host 40 -> 28-31 ms/frame).
4. **JIT (dynarmic)**: precise GetSetElimination (+12% fps), TBI unmasked with per-instruction mask
   learning (+2..+6 fps, -10% game CPU), inline indirect-branch dispatch, scalar FP kept in XMM.
5. Binder host-call thread pool, Vulkan command batching, direct cross-process guest memory access
   (`remote_direct`), zero-copy GPU present (`present_zero`), vsync paced to deadlines (it drifted to
   58.8 Hz).
6. **Bugs found on the way**: our epoll ignored `EPOLLET` -- Android's DNS-over-HTTPS resolver
   (tokio/mio) spun a full core in ~1 of 3 boots; two JIT bugs (an unused load could skip its fault --
   ART's stack-overflow probe; a forwarded NZCV value); Vulkan batch leaks on pool reset/destroy.
7. **RAM**: zero-page sweep, JIT constant pool not touched, no-commit guest reads, zero buffers, the
   kernel's binder spawn rule (919 -> 535 threads), a smaller dispatch table in the system host, an
   uncompressed boot image mapped as shared views (saved devices now carry `-bootu`).

## Later in the morning (08:00-09:00)

- **Code aging in the system host** (default every 10 min): system_server's translations 118 -> 29
  MiB on the first pass. With the JIT table compaction (dynarmic 0051/0052) the system host's
  private working set is now ~1.05 GB (from ~1.2), all hosts **3.38-3.40 GB** in fresh boots
  (`startup-1009.csv` base arms, 58-59 fps, 47-49 ms/frame).
- **A review pass** (agents reading code they did not write) found and fixed five real bugs in
  tonight's default-on changes, each with a test: present_zero could switch itself off for good after
  a few resizes; a fork's memory restore could overwrite a binder reply written by `remote_direct`;
  the kernel binder spawn rule could freeze a pool after a failed read; a `ppoll` on no descriptors
  missed signals for up to 1 s; the boot-image cache leaked temp files on a failed write. The JIT
  patches, the futex/poll rewrite, the window pump, the vsync pacer and the binder pool were reviewed
  and found sound.
