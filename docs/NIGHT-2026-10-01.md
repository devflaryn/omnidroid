## Phase B core: `omni-debug` (emulation-layer debug engine) — landed on `mcp-server`

New crate `crates/omni-debug` (host-agnostic; no cfg(target_os), no OS crate). A `Session` loads a
library on the translating backend (per-thread cache so breakpoints are allowed — a shared cache
refuses them, D38) and exposes: resolve_symbol, list_symbols, list_maps, read_mem/read_words,
write_mem (forced write into RO code via COW + invalidate), dump_module, call_function (crafted
inputs), alloc_data + load_code (place a buffer / a code snippet), set_breakpoint/clear, run_until_stop
+ resume (interactive stepping), get_registers, backtrace (FP-chain walk), intercept (entry/exit +
replace_return), trace_calls, trace_syscalls.

Gate `crates/omni-debug/tests/lab.rs`, 12 tests, **all green on Windows**, driven against a checked-in
real AArch64 fixture (AOSP 15 `libz.so`, 117 KiB). call_function is checked against an independent
oracle (adler-32 computed in the test), not against zlib — the M2 rule.

Rulings made while building it (what / why / cost-if-wrong):
- **Driver resumes past a breakpoint by `run(from=bp_addr)`, not a manual single-step.** A manual
  `run(bp, Instructions(1))` overshoots to the end of the block (dynarmic counts per block) and can
  land silently on the *next* breakpoint, which the following `run` then suppresses (cpu.rs
  `suppressed_breakpoint`) — so an exit hook was missed. Using the backend's own suppress-and-resume
  fixed it. Cost if wrong: exit/trace events silently dropped.
- **call_function runs to completion (breakpoints are trace points via intercept); run_until_stop +
  resume is the interactive stepping path that pauses on user breakpoints.** Clear split; both service
  watches. Cost if wrong: confusing dual-purpose API.
- **Test targets: adler32 (perfect oracle) + zlibVersion (pointer) + crafted stubs.** compressBound
  was dropped as an oracle — this is **zlib-ng**, whose compressBound slack differs from stock zlib
  (got 4142 vs stock 4110 for 4096). adler32(NULL,0) and adler32's functable dispatch are skipped:
  the lab runs no init_array (needs the compat layer's imports), so functable pointers are null —
  a wild branch is a *typed* error (tested), never a host crash. Cost if wrong: brittle/false oracle.

## Phase A: `omni-mcp` (MCP server over stdio) — landed on `mcp-server`

New crate `crates/omni-mcp` (lib + `omni-mcp` binary). Speaks JSON-RPC 2.0 over stdio, one message
per line (MCP stdio transport). Self-contained JSON codec (`src/json.rs`) — no serde added, matching
the launcher's "without a JSON crate" choice, so the other two machines gain no new deps.

Tools (25): lifecycle/session (start_instance, stop_instance, list_instances, install_apk,
launch_app, login, join_place, screenshot) driving the `omnidroid` launcher; and the emulation-layer
debug/dump family over omni-debug (lab_load, resolve_symbol, list_symbols, list_maps, read_mem,
write_mem, dump_module, call_function, set_breakpoint, run_until_stop, resume, get_registers,
backtrace, intercept, trace_syscalls, alloc_data, load_code).

Verified on Windows:
- Unit tests (json + transport + server helpers): 16/16.
- e2e (`tests/e2e.rs`, drives the server's dispatch): 4/4 — initialize, tools/list, lab_load,
  resolve_symbol, list_maps, alloc_data + call_function (adler-32 == oracle over MCP), dump_module,
  read_mem (ELF magic), write_mem (patch RET), missing-lab error.
- **Real binary over stdin/stdout**: piped initialize + notifications/initialized + tools/list +
  lab_load + resolve_symbol; got serverInfo omni-mcp, 25 tools, libz.so 91 exported symbols,
  zlibVersion resolved. The transport works against the actual process.

README + `.mcp.json` / `claude mcp add` snippet: `crates/omni-mcp/README.md`.

Rulings (what / why / cost-if-wrong):
- **Hand-rolled JSON, no serde.** Matches main.rs; keeps Cargo.lock unchanged for Linux/Mac; MCP
  JSON is simple. Cost if wrong: a JSON bug in an external protocol — mitigated by the json test
  suite (round-trip, escapes, surrogate pairs, malformed-input rejection).
- **Addresses cross the wire as hex/decimal strings.** A 64-bit guest address exceeds a JSON
  number's 2^53 exact-integer range. `Json::as_u64` accepts number, "0x..", or decimal string.
- **install_apk/login/join_place record config for the next boot** rather than mutating a live
  device: the real-AOSP path installs+signs-in+joins as one boot (r_roblox), with no external IPC to
  a running instance. Cost if wrong: an agent expecting live re-config is surprised (documented).
- **Small enabling change to `r_roblox.rs`: honour a preset `OMNI_SCREENSHOT`** so the server names
  the framebuffer PNG up front (else the path depends on the test's pid). Backwards-compatible.
