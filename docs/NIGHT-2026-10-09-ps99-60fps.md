## Findings before the first A/B

- **Every guest timed wait is rounded up to Windows' 15.6 ms tick.** omni-linux never raises the
  host timer resolution, and guest `futex` timeouts, `nanosleep`, condition-variable `wait_for`
  are `park_timeout` / parking_lot waits (WaitOnAddress). Probe on this host (scratch `parkres`):
  `park_timeout(1 ms)` 15.49 ms median, `parking_lot` `wait_for(1 ms)` 15.57 ms, `park_timeout(2 ms)`
  15.41 ms; `std::thread::sleep(1 ms)` 1.55 ms (std uses a high-resolution waitable timer). With
  `timeBeginPeriod(1)`: 1.50 / 1.54 / 2.47 ms. A windowless process (every guest host but the
  system's) is also EcoQoS-eligible and Windows 11 may ignore its resolution request. Levers
  `timer_ms=<n>` and `qos=high|auto` (lever.rs) A/B both.
- **Futex wakes were a thundering herd.** One condition variable per process; every wake was
  `notify_all`, waking every futex waiter, every `nanosleep` and every PI waiter in the process.
  Rewritten: each waiter parks its own host thread, a wake unparks only those it woke
  (`futex.rs`); lever `futex_herd=1` restores the herd for the A/B.
