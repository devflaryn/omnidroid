# A2.2 — Identity + Command Surface (the diskless finish) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Complete the diskless model: make the central store (`accounts.py`) the single source of account identity, retire the `accounts/<name>/` folder entirely, fold `play` into `start` (join with `--place`, else Roblox home), source the session (token + place) from the store, and delete the persistent-folder-model commands (`create`, `play`, `resume`, account-migration) that no longer make sense when every instance boots the shared base fresh.

**Architecture:** After A2.2a, per-boot state already lives in `runtime/<username>/` and ports allocate dynamically. What remains is the *identity* half: `load_account`/`save_account`/`all_accounts` still read/write `accounts/<name>/account.json`. This plan turns `load_account(name)` into a **store+runtime handle builder** — identity (`base`) from the store, live ports/pid from `runtime/<username>/run.json` — so the ~14 commands that only need a handle to talk to a *running* instance keep working unchanged. `save_account` (persistent per-account writes) is retired; identity mutations go to the store via `accounts.set_fields`. The persistent-model commands and their `save_account`/migration callers are deleted. `start` absorbs `play` and builds its launch handle from store identity + freshly allocated ports.

**Tech Stack:** Python 3.13+, QEMU (arm64/UEFI, snapshot=on), pytest/unittest, the `accounts.py` store (username-keyed, with `place_id`/`base`/`proxy`/`group`/`notes` + `set_fields` from A2.1).

## Global Constraints

- **The store is identity.** `base` (prod/dev), `place_id`, `token`(=cookie) come from `accounts.py`. No `accounts/<name>/account.json`, no `session.json`. The only per-instance disk artifact is `runtime/<username>/` (A2.2a), wiped on stop.
- **`load_account(name)` returns a handle, never reads a folder.** Contract: `{name, base, adb_port, qmp_port, vnc_port, ephemeral: True, dev, game_package}`. `base`/`dev` from the store record; `adb_port`/`qmp_port`/`vnc_port` from `runtime/<username>/run.json` when the instance is running (else the handle carries no live ports — callers that need a running instance already guard on `running_pid`). The key shape is preserved so the ~14 running-instance commands (`adb`, `install`, `screenshot`, `logcat`, `capture`, `autocap`, `view`, `kioskify`, `run-app`, `dev-ui`, `watch`, `test-apk`, `stop`, `session`) need no change.
- **Ephemeral-only.** Every instance boots the shared base `snapshot=on`, no overlays. `ensure_instance`/`_create_arm`'s overlay branches and the x86 overlay path are removed for instances (base-BUILD commands, which operate on base images, are out of scope and unchanged).
- **`start` with no `--place` → Roblox mobile home** (logged in via cookie, sitting on home). `--place <id>` joins that place. `start` on an already-running username is rejected.
- **Session from store.** `deliver_session` reads token+place from the store record (not `session.json`). `login` persists `--place`/`--base` into the store via `set_fields`; `session <user>` reads/writes the store.
- **Deleted commands:** `create`, `play`, `resume`, and account-migration (`migrate_account`, `migrate_account_fast`, `update-all` as an account-migration, and the persistent parts of `bench-ksm` if they create persistent accounts). **Kept unchanged:** base-BUILD/maintenance commands that operate on *base images* — `brand-base`, `bake-game`, `rebuild-base`, `build-dev-base`, `update-base` (the base-image updater), `update-kiosk` (base), `use-base`, `bases`, `setup`, `doctor`, `qemu-info`, `view`, `_vncview`.
- **`username` is the identifier** (required positional), matching the store key. `remove <user>` deletes the store entry (and wipes any runtime dir).
- **Suite stays green after every task.** Tests asserting the old folder/create/play/resume/session.json model are updated to the store model in the same task that changes the behavior. A real `login → start <user> --place <id>` join on the arm host should be exercised in review if feasible (the known-good prod flow must survive).
- **Run tests with:** `python3 -m pytest tests/ -q` from the repo root.

- **Spec coverage:** completes the spec's diskless model — store as identity, `start` absorbs `play` with home/`--place`, session from store, no folders/`session.json`, `remove` → store delete. Together with A2.2a (runtime dirs + dynamic ports) this fully delivers "100+ accounts, no disk each."
