# Linux kernel personality, milestone A5 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Signals are delivered as the arm64 Linux kernel delivers them: a guest fault reaches the guest's own `SIGSEGV` handler (on its alternate stack when asked) and `rt_sigreturn` resumes the faulting instruction; `raise`, `pthread_kill` and `kill` reach the right thread's handler; a blocked signal waits for its unblocking; a signal ends a blocked `futex` wait with `EINTR`.

**Architecture:** A `signal` module owns the arm64 frame: `rt_sigframe { siginfo (128), ucontext }`, `ucontext { uc_flags, uc_link, uc_stack (24), uc_sigmask (8) + 120 pad, uc_mcontext @176 }`, `sigcontext { fault_address, regs[31], sp, pc, pstate, __reserved[4096] }` holding an `fpsimd_context` record (magic `0x46508001`, size 528: `fpsr`, `fpcr`, `vregs[32]`) and a null terminator, then a frame record `{x29, pc}`. Each task gets a shared `pending` set (an `AtomicU64` other tasks can set) and the process's dispositions become readable. Delivery happens in the run loop: after a syscall that leaves a deliverable signal (the syscall entry defers), when another task halts this one to post a signal, and on a synchronous fault (`MemoryFault` → `SIGSEGV`, an undecodable instruction → `SIGILL`). `rt_sigreturn` defers too, and the loop restores every register, `NZCV`, the vector registers and the mask from the frame.

**Tech Stack:** Rust; NDK r28c for the fixture.

**Spec:** `docs/superpowers/specs/2026-09-27-linux-abi-layer-design.md` (§1 A5, §2 `signal`, §3 "Fault to signal").

## Global Constraints

- As A1-A4. Default actions stay as A1 wired them (terminate, ignore, stop recorded). `SA_RESTART` restarts only `futex` waits and `nanosleep`-family calls a signal interrupted (the others return `EINTR`), recorded as a known narrowing.
- `si_addr` is untagged (no `SA_EXPOSE_TAGBITS`); `fpcr`/`fpsr` are written 0 and ignored on return (the CPU seam exposes neither), recorded.

## Review Focus

1. **The frame is 16-byte aligned and below the interrupted `sp`** (or at the top of the alternate stack with `SA_ONSTACK` when not already on it). Test in Task 1.
2. **`rt_sigreturn` restores `NZCV` and `v0`–`v31`**, not only `x` registers: a handler that clobbers them must not corrupt the interrupted code. Test in Task 2.
3. **A signal to another thread** runs on that thread (`gettid()` in the handler), even when it is blocked in `pthread_cond_wait`. Test in Task 3.
4. **A blocked signal is delivered once, when unblocked**, not dropped and not twice. Test in Task 3.
5. **A fault with no handler still ends the process** with `Killed { signal: 11 }` and the register dump. Test in Task 2.

### Task 2: Delivery and `rt_sigreturn` in the run loop
**Files:** `process.rs` (per-task `pending: Arc<AtomicU64>` in the task table; `deliver`; `rt_sigreturn` restore; synchronous `SIGSEGV`/`SIGILL`), `sys.rs` (`rt_sigreturn`, `rt_sigpending`, `rt_sigsuspend`, `kill`/`tkill`/`tgkill`/`rt_tgsigqueueinfo` post to the target task and halt it; dispositions read by the loop; `sigprocmask` unblocking a pending signal defers to deliver it), `futex.rs` (waiters carry their tid; `interrupt(tid)`). Tests in `tests/threads.rs`-style unit tests where hand-assembled guest code can exercise a fault handler.
