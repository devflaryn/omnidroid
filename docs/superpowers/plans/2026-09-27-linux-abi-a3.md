# Linux kernel personality, milestone A3 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** The real AOSP `/system/bin/getprop ro.build.version.sdk` prints `35`: the real bionic finds, maps and reads a property area this layer writes in bionic's own format.

**Architecture:** A `props` module builds three read-only files at spawn from the sysroot's `build.prop` files plus a small overlay: `/dev/__properties__/property_info` (the serialized context trie, one context), `/dev/__properties__/properties_serial` (an empty prop area) and `/dev/__properties__/u:object_r:default_prop:s0` (the prop area holding every property). They are served through `ProcFs` (the A2 mechanism, extended to `/dev/__properties__`) as sized in-memory files (`Node::Blob`) that `open` snapshots and `mmap` copies privately — a `:` in the context file name never reaches a host path.

**Tech Stack:** Rust, `omni-linux`.

**Spec:** `docs/superpowers/specs/2026-09-27-linux-abi-layer-design.md` (§1 A3; §2 `props` row).

## Global Constraints

- As A1/A2: the `unified` worktree, PowerShell cargo with `$env:OMNIDROID_DYNARMIC_BUILD_DIR='C:\od-unified';` (separate `--target-dir` while a game run holds the lock), `omni-android` untouched, named refusals, the two attribution lines.
- Formats are bionic's (Android 15): `prop_area` header 128 bytes (`bytes_used`, `serial`, magic `0x504f5250`, version `0xfc6ed0ab`, 28 reserved words); data begins with the root `prop_bt` (20 bytes) then a 92-byte dirty-backup area; `prop_bt { namelen, prop, left, right, children, name[] }` and `prop_info { serial = valuelen << 24, value[92], name[] }` allocated 4-aligned, offsets relative to the data start; one trie level per `.`-separated component, siblings a binary tree ordered by (length, bytes); `ro.*` values of 92 bytes or more use the long form (`serial` = error-message length << 24 | 1 << 16, `value` = the legacy error text, an offset from the `prop_info` to the value at byte 56). `property_info`: header `{ current_version 1, minimum_supported_version 1, size, contexts_offset, types_offset, root_offset }`, string tables `[count, offsets…]`, root `TrieNodeInternal` whose `PropertyEntry` is `("root", context 0, type 0)` with no children, prefixes or exact matches.
- File checks bionic makes: owner uid/gid 0, not group/other writable, size ≥ the header; `/dev/__properties__` is a directory; `access(property_info, R_OK)` succeeds.

## Review Focus

1. **Property order across files**: later `build.prop` files override earlier ones as init loads them (system, system_ext, vendor, product); the overlay wins last. Test in Task 1.
2. **Sibling ordering is bionic's `cmp_prop_name`** (shorter name first, then bytes): a Rust reader implementing bionic's `find_property` must find every property written. Test in Task 1.
3. **A long `ro.*` value** reads back via the long form; a long non-`ro.` value is dropped and recorded. Test in Task 1.
4. **`mmap(PROT_READ, MAP_SHARED)` of a blob** succeeds (as a private copy) and `PROT_WRITE` of it is `EACCES`. Test in Task 2.
5. **`stat` of a blob** reports its real size, uid 0, mode `0444`. Test in Task 2.
