# D2 Gralloc Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** a guest process allocates a graphics buffer through the real libui (gralloc 5), and its
memory is a `crate::shm` region the guest and the host both map.

**Architecture:** the host serves AIDL `IAllocator` V2 on the D1 binder endpoint; omnidroid's
device overlay adds a VINTF declaration and `mapper.omni.so` (stable-C AIMapper v5, C, NDK-built)
over the pinned image; each buffer is one `Shm` (metadata page + pixels) sent as a file descriptor.

**Tech Stack:** Rust (omni-linux), C (NDK r28c, `aarch64-linux-android35-clang`), AOSP 15 image.

**Spec:** `docs/superpowers/specs/2026-09-27-d2-gralloc-design.md`

## Review Focus

- A guest sends a malformed `allocate2` parcel (truncated, negative width, count 0 or 1000): the host answers `EX_ILLEGAL_ARGUMENT` or `UNSUPPORTED`, never panics. Pinned in Task 3's unit tests.
- A handle with a wrong magic, wrong numFds/numInts, or a region smaller than it claims: `importBuffer` answers `BAD_BUFFER`, never maps. Pinned in Task 4 through the fixture's negative import check.
- A host service replying with an fd to a caller that died: the reply is dropped, the `Shm` freed (no panic, no leak of the queue). Pinned in Task 1.
- Width x height x bpp overflow (e.g. 65536 x 65536 x 8): rejected before any allocation. Task 3.
- A directory listing of `/vendor/lib64/hw` shows the overlay's file beside the image's. Task 2.

### Task 1: host services see and send objects

**Files:** modify `crates/omni-linux/src/binder.rs`; test `crates/omni-linux/tests/binder_host_objects.rs` (one test per file: the broker is per host process).

**Produces:**
```rust
pub struct HostCall { pub code: u32, pub data: Vec<u8>, pub fds: Vec<Arc<OpenFile>>, pub handles: Vec<u32>, pub sender_pid: i32, pub sender_euid: u32 }
pub struct HostReply { pub data: Vec<u8>, pub fds: Vec<(usize, Arc<OpenFile>)> } // offset of a flat_binder_object TYPE_FD in data
impl HostReply { pub fn bytes(data: Vec<u8>) -> Self }
impl Broker {
    pub fn create_host_service_objects(&self, handler: impl Fn(HostCall) -> HostReply + Send + Sync + 'static) -> u64;
    pub fn add_service_with_stability(&self, name: &str, ptr: u64, stability: i32) -> Result<(), String>;
}
pub const STABILITY_VINTF: i32 = 0b11_1111;
```
`create_host_service` (bytes) becomes a wrapper. Incoming binder/handle objects are translated for `HOST` with `translate_ref` (so a handle lands in the host's table), fds are collected in object order; the reply's fds become `Txn.fds` for the caller's `deliver` to install.
