# Linux kernel personality, milestone A4 — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Real bionic threads work: `pthread_create`/`join`, mutexes, condition variables and `__thread` storage in a small C program built with NDK r28c pass, and `exit` from a secondary thread ends the whole process.

**Architecture:** A process owns a task table. `clone` with the thread flag set creates a guest-managed CPU context on the same `DynarmicBackend`, copies the parent's registers (captured by the syscall entry for `clone` only), sets `sp`, `TPIDR_EL0` and `x0 = 0`, and runs it on a host thread. `futex` becomes a real wait queue keyed by the untagged address (wait, wake with counts, bitsets with absolute deadlines, requeue, compare-requeue, wake-op). Thread exit clears and wakes `clear_child_tid`; `exit_group` sets the process's exit, halts every other task through its `HaltHandle` and wakes every waiter so blocking calls return.

**Tech Stack:** Rust; NDK r28c (`aarch64-linux-android35-clang`) for the two fixtures only.

**Spec:** `docs/superpowers/specs/2026-09-27-linux-abi-layer-design.md` (§1 A4, §2 `task`, §3 "Thread start", "Thread and process exit").

## Global Constraints

- As A1-A3. The fixtures' binaries are committed beside their sources with their sha256 and the exact compile command (`tests/fixtures/build.txt`); the runtime never depends on the NDK.
- Fork-shaped `clone` (no `CLONE_VM|CLONE_THREAD|CLONE_SIGHAND`) answers `-ENOSYS`, recorded as `clone: flags <hex> (fork)`; `clone3` answers `-ENOSYS` (bionic falls back to `clone`).

## Review Focus

1. **A waiter woken by `FUTEX_WAKE` before it sleeps** (value changed between check and wait) must not sleep forever: the value check and the enqueue happen under the same lock the waker takes. Test in Task 1.
2. **`FUTEX_WAIT_BITSET`'s timeout is absolute** (CLOCK_MONOTONIC, or REALTIME with the flag) while `FUTEX_WAIT`'s is relative. Test in Task 1.
3. **`exit_group` while other threads block in `futex`/`nanosleep`** ends the process promptly (no hang). Test in Task 3 (fixture 2).
4. **`clear_child_tid` is written 0 and woken** when a thread exits, which is what `pthread_join` waits on. Test in Task 3 (fixture 1 joins 8 threads).
5. **A tagged futex address** (`0xb4…`) keys the same queue as the untagged one. Test in Task 1.
